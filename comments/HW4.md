Реализация сервиса device-service

Цель: Реализовать микросервис device-service, который:

предоставляет CRUD API для работы с устройствами,
читает и обновляет данные из шардированной базы данных PostgreSQL,
поддерживает горизонтальное масштабирование и синхронизацию данных между шардами,
экспонирует метрики, обеспечивает отказоустойчивость, логирование и удобную эксплуатацию.
Технологии:
Язык программирования: Java 24
Фреймворк: Spring Boot 3.5
База данных: PostgreSQL (шардированная)
Драйвер: ShardingSphere-JDBC или аналогичный (поддержка шардирования JDBC)
Интерфейс API: REST (Spring Web)
Аутентификация: Keycloak (OAuth2 / OIDC, JWT)
Кэширование: Redis
Метрики и мониторинг: Spring Actuator + Micrometer
Логирование: структурированное (JSON, stdout)
Тестирование и окружение: Testcontainers (PostgreSQL, Keycloak, Redis)
Система сборки: Gradle
Структура хранилища (PostgreSQL)
Таблица: devices (во всех шардах)

device_id (text, PK) — уникальный идентификатор устройства (строго уникален в кластере)
device_type (text) — тип устройства
created_at (bigint) — время регистрации (UNIX ms)
meta (jsonb/text) — метаданные устройства
Требования:
Каждая шардированная БД хранит свою часть устройств.
Все операции изменения данных идут через Kafka и device-collector-service, прямого доступа к БД нет.
Гарантировать идемпотентность операций и целостность данных при масштабировании.
Основные задачи и функции
1. API для управления устройствами

POST /devices — создание нового устройства
GET /devices/{deviceId} — получение информации по устройству
PUT /devices/{deviceId} — обновление данных устройства
DELETE /devices/{deviceId} — удаление устройства
2. Работа с БД

Все операции выполняются через шардированный доступ с помощью JDBC (ShardingSphere).

3. Безопасность

Все эндпоинты защищены OIDC (JWT) через Keycloak.
Проверка токена на каждом запросе, доступ по ролям.
4. Метрики и мониторинг

Экспонирование стандартных метрик, healthchecks (/actuator/health, /actuator/metrics).
Метрики по операциям CRUD (количество успешных/неуспешных запросов, время выполнения, ошибки БД).
Readiness/liveness-пробы для Kubernetes/Compose.
5. Логирование и аудит

Все действия логируются в структурированном формате (JSON) для сбора и анализа через централизованные системы (Loki).
Отдельный аудит успешных/неуспешных операций по устройствам.
